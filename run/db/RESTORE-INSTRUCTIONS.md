# Restoring the MedQ Database from `medq-backup.sql`

This archive includes a SQL backup of the live MedQ database at `db/medq-backup.sql` (~5.7MB, 3463 rows across 121 tables).

## What's in the backup

- **12 users** including the 3 demo accounts:
  - `student@medq.com` / `test123` (student role)
  - `educator@medq.com` / `test123` (educator role)
  - `admin@medq.com` / `test123` (admin role)
- **1208 questions** (MCQ + true/false, across all organ systems)
- **11 exams** + **4 exam attempts** + **164 exam questions**
- **119 question attempts** (drives adaptive difficulty calibration)
- **14 group questions**, **7 push subscriptions**, study sessions, streaks, achievements, etc.

## What's NOT in the backup (excluded to keep size reasonable)

- `KnowledgeChunk` / `KnowledgeSource` / `KnowledgeEmbedding` — large document-ingestion artifacts (can be regenerated by re-ingesting documents via the Knowledge tab)
- `AgentJobEvent` / `AgentAuditLog` / `AgentMemory` — verbose agent runtime logs
- `SecurityEvent` / `AiCallLog` — telemetry/security logs
- `Request` / `RequestAttempt` / `ServerLog` — FreeLLM API request logs

## How to restore

### Option A: Using `psql` (if installed)

```bash
# After `bash scripts/setup-postgres.sh` and `prisma db push` have created the schema:
psql "postgresql://postgres:postgres@127.0.0.1:5432/nextapp" -f db/medq-backup.sql
```

### Option B: Using the embedded Node.js `pg` client (no psql needed)

The archive includes `db/restore.mjs` which restores via the `pg` npm package
already installed as a dependency of `.pg-embed`. Run it from the project root:

```bash
node db/restore.mjs
```

This connects to `postgresql://postgres:postgres@127.0.0.1:5432/nextapp`,
runs the backup SQL statement-by-statement, and prints progress.

## Order of operations for a fresh install

```bash
# 1. Install deps (bun preferred)
bun install
cd .pg-embed && bun install && cd ..
cd freellmapi && npm install --omit=optional && npm install better-sqlite3 && cd ..

# 2. Start PostgreSQL + create schema
bash scripts/setup-postgres.sh
bunx prisma generate
bunx prisma db push

# 3. Restore the data (Option A or B above)
psql "postgresql://postgres:postgres@127.0.0.1:5432/nextapp" -f db/medq-backup.sql
#   OR:  node db/restore.mjs

# 4. Build + start
bash scripts/build-prod.sh
bash scripts/restart-prod.sh
```

## Alternative: seed from scratch instead

If you'd rather start with a minimal fresh dataset (3 demo users + a few sample
questions) instead of restoring the full backup, use the seed scripts:

```bash
bunx tsx prisma/seed.ts              # 3 demo users + ~10 sample questions
bunx tsx prisma/seed-content.ts      # additional content
bunx tsx prisma/seed-chat.ts         # chat rooms/messages
bunx tsx prisma/seed-flashcards.ts   # flashcard decks
```
